# ATLAS Graph and Data Debugging Manual

This is the symptom-first reference for debugging plugins generated by PluginGenerator. It covers cursor values, visible-range graphs, compare sessions, signal subscriptions, statistics, WPF rendering, computed series, titles, legends, and units.

Use full-text search. Important diagnostics have stable identifiers such as `GRAPH-DATA-001`, so they remain easy to find even if this document is reorganized.

## The three data pipelines

### Cursor pipeline

```text
ATLAS cursor moves
 -> TemplateDisplayViewModelBase.OnCursorDataPointChanged
 -> throttled cursor request
 -> OnMakeCursorDataRequestsAsync
 -> CreateSampleRequestSignal
 -> SignalBus.Send
 -> SampleResultSignal
 -> HandleSampleResultSignal
 -> TimebaseSeriesViewModel.UpdateCurrentValue
 -> cursor value / overlay
```

The cursor asks for one sample at or immediately before the cursor. A working cursor proves only this pipeline works.

### Visible-range graph pipeline

```text
Visible time range changes
 -> TemplateDisplayViewModelBase.OnTimebaseRangeChanged
 -> throttled timebase request
 -> OnMakeTimebaseDataRequestsAsync
 -> CreateDataRequestSignal(..., SampleMode.Mean)
 -> SignalBus.Send
 -> DataResultSignal
 -> HandleDataResultSignal
 -> copy ParameterValues while locked
 -> TimebaseSeriesViewModel.Update
 -> Values/Timestamps notifications
 -> view code-behind Redraw
 -> GraphRenderer.Draw
 -> VisualLayer
```

### Compare-session pipeline

```text
Cursor/session set changes
 -> OnMakeCursorDataRequestsAsync
 -> CreateCompositeSampleRequestSignal
 -> CompositeSampleResultSignal
 -> one result per composite session
 -> CompareRowViewModel.Update
 -> compare table
```

Compare code uses `MAT.OCS.Core.CompositeSessionKey`. It is not interchangeable with a similarly named type from another assembly.


## Graph data diagnostics

### GRAPH-DATA-001: `Data` is null

Inspect the request's sample mode first. The generator uses:

```csharp
SampleMode.Mean
```

This produces samples in `ParameterValues.Data`, which the renderer consumes. `SampleMode.MaximumToMinimum` has a different result shape and may populate extrema storage instead of `Data`. Requesting maximum-to-minimum and reading `Data` is internally inconsistent.

Checklist:

1. Break in `OnMakeTimebaseDataRequestsAsync`.
2. Confirm `PrimaryParameters` is not empty.
3. Confirm `compositeSession.TimebaseRange` is valid and non-empty.
4. Confirm `DataRequestSampleCount > 0`.
5. Confirm the request uses `SampleMode.Mean`.
6. Break in `HandleDataResultSignal`.
7. Inspect `SampleCount`, `Data`, and `Timestamp` while locked.

The generated guard is intentional:

```csharp
if (parameterValues.SampleCount == 0 || parameterValues.Data == null)
{
    return;
}
```

Do not remove it just to continue debugging. Determine why ATLAS returned no usable samples.

### GRAPH-DATA-002: timestamp/value length mismatch

The renderer pairs entries by index. Inspect:

```text
parameterValues.Timestamp.Count
parameterValues.Data.Count
series.Timestamps.Count
series.Values.Count
```

Copy both arrays inside the lock. Never retain ATLAS-owned collections after unlocking. If custom transformations alter one array, they must alter the other consistently.

### GRAPH-DATA-003: every value is non-finite

Statistics deliberately ignore both `NaN` and positive/negative infinity, matching the renderer:

```csharp
var validValues = values.Where(value => !double.IsNaN(value) && !double.IsInfinity(value)).ToArray();
```

If every value is invalid, displayed sample count is zero and statistics remain `NaN`. Verify the exact parameter identifier, active session, visible range, and whether the session actually records that parameter there.

## Pipeline diagnostics

### GRAPH-PIPE-001: cursor works but range does not

These are independent paths:

| Cursor | Visible range |
|---|---|
| `CreateSampleRequestSignal` | `CreateDataRequestSignal` |
| `SampleResultSignal` | `DataResultSignal` |
| one nearby sample | sampled range |
| `HandleSampleResultSignal` | `HandleDataResultSignal` |
| `UpdateCurrentValue` | `Update` |

Check the range-only boundaries in order:

1. Does `OnMakeTimebaseDataRequestsAsync` run?
2. Is the timebase range non-empty?
3. Is `SampleMode.Mean` requested?
4. Does `HandleDataResultSignal` run?
5. Does its `SourceId` filter pass?
6. Does the request parameter GUID match a `Series` GUID?
7. Does `Update` receive finite values?
8. Does `Redraw` run?

### GRAPH-PIPE-002: range changes make no request

`TemplateDisplayViewModelBase` reacts to session, parameter, visibility, and timebase notifications. Requests pass through a throttle, normally 200 ms (5 Hz).

Break in this order:

```text
TemplateDisplayViewModelBase.OnTimebaseRangeChanged
TemplateDisplayViewModelBase.MakeDataRequests
TemplateDisplayViewModelBase.MakeTimebaseDataRequests
GeneratedViewModel.OnMakeTimebaseDataRequestsAsync
```

The base can correctly avoid requests when the display is not visible or no primary composite session is available.

### GRAPH-PIPE-003: sample-count changes do nothing

The generated property setter calls:

```csharp
this.MakeDataRequests(false, true);
```

That means “cursor unchanged, timebase changed.” Confirm the setter runs and the value is positive. It is persisted with `SaveProperty` and restored using `ReadProperty`.

## Signal diagnostics

### SIGNAL-001: source identity filtering

The subscription filters results to this display instance:

```csharp
signal => signal.SourceId == this.ScopeIdentity.Guid
```

Requests use the same identity. If custom code sends a different source ID, ATLAS may return data but this ViewModel will intentionally ignore it.

### SIGNAL-002: subscription counts

Subscriptions are not duplicated. The constructor creates one per result type:

| Behavior | `DataResultSignal` | `SampleResultSignal` | `CompositeSampleResultSignal` |
|---|---:|---:|---:|
| Current value | 0 | 1 | 0 |
| Visible range | 1 | 0 | 0 |
| Current + range | 1 | 1 | 0 |
| Compare sessions | 0 | 0 | 1 |

Combined behavior has two subscriptions because it consumes two different signal types. Refreshing, scrolling, and changing the range send requests; they do not resubscribe.

Subscriptions are stored in `Disposables`, so ViewModel disposal removes them. Audit generated code with:

```powershell
rg -n "Subscribe<(DataResultSignal|SampleResultSignal|CompositeSampleResultSignal)>" .
```

### SIGNAL-003: request sent but handler never runs

Compare these values:

```text
ScopeIdentity.Guid
request SourceId
signal.SourceId
parameter.InstanceIdentifier
session key
timebase range
```

Then verify the subscription exists before sending, has not been disposed, consumes the correct result type, and passes its predicate. Generated handlers catch exceptions and log through `ILogger.Trace`; inspect ATLAS logs as well as Visual Studio output.

### SIGNAL-004: stale result overwrites newer data

Rapid range changes can leave multiple requests in flight. Source identity identifies the display, not request generation. If stale ordering is observable, add a request-generation token or compare the result request range with the current range. This advanced rejection policy is not currently generated.

## Matching and statistics

### GRAPH-MATCH-001: result does not match a series

`SyncSeries` creates a `TimebaseSeriesViewModel` for each primary parameter. Results match using:

```csharp
item.ParameterIdentifier ==
    signal.Data.Request.Parameter.InstanceIdentifier
```

If `series` is null, `SyncSeries` may not have run, parameters may have changed during an in-flight request, or custom code requested another parameter. Do not match by name: names can change and need not be unique; GUIDs are the correlation mechanism.

### GRAPH-STATS-001: samples stay at zero

The legend's `SampleCount` is the count of finite values, not blindly the raw ATLAS count. Break in `TimebaseSeriesViewModel.Update` and inspect:

```text
values.Length
values.Count(value => !double.IsNaN(value) && !double.IsInfinity(value))
```

If `Update` never runs, work backward through GUID matching and signal handling. If valid values arrive but UI remains zero, inspect property notifications and bindings.

### GRAPH-STATS-002: statistics are `NaN`

The generated calculations are:

```csharp
Minimum = validValues.Length == 0 ? double.NaN : validValues.Min();
Maximum = validValues.Length == 0 ? double.NaN : validValues.Max();
Average = validValues.Length == 0 ? double.NaN : validValues.Average();
```

These are local statistics over rendered/downsampled values. They are not a separate extrema request.

### GRAPH-STATS-003: statistics differ from raw extrema

ATLAS returns at most `DataRequestSampleCount` mean samples over the visible range. Statistics over this downsampled set can differ from statistics over every raw sample. Increase sample count for a closer approximation or implement a separate exact-extrema request when required.

## Rendering diagnostics

### GRAPH-RENDER-001: data exists but nothing is drawn

Check four boundaries:

1. `TimebaseSeriesViewModel.Values` contains finite values.
2. View code-behind `Redraw` creates non-empty `GraphSeries` objects.
3. `GraphVisualLayer.Visual.Extents` has positive width and height.
4. `GraphRenderer.Draw` receives valid series.

Also check timestamps vary, colors are visible, the graph is arranged, custom renderer code does not return early, and the chosen graph type supports the data shape.

### GRAPH-RENDER-002: redraw notifications

The view listens to `Series.CollectionChanged` and each series' `PropertyChanged`. It redraws for:

```csharp
nameof(TimebaseSeriesViewModel.Values)
nameof(TimebaseSeriesViewModel.Timestamps)
nameof(TimebaseSeriesViewModel.CurrentTimestamp)
```

If a newly added property affects geometry, add it to `OnSeriesPropertyChanged` or explicitly redraw. `Name` and `Unit` update bound legend text but do not affect geometry.

### GRAPH-RENDER-003: cross-thread collection exception

Signal handlers are not assumed to run on WPF's UI thread. Generated code copies data under the ATLAS lock, unlocks, then calls:

```csharp
await this.ExecuteOnUiAsync(() => { ... });
```

Keep all `ObservableCollection` and UI-bound changes inside that callback. Never dispatch to the UI while holding the ATLAS values lock.

### GRAPH-RENDER-004: strange scale

The renderer determines extents from valid input. Outliers can flatten the useful trace. Inspect each series' min/max, filter bad points where appropriate, or customize `GraphRenderer.cs` with domain-specific axes.

## Metadata

### GRAPH-META-001: title, legend, and units

The GUI supports a graph title, comma-separated series units in parameter order, and an optional legend/statistics panel.

```text
Parameters: vCar:Chassis, nEngine:Chassis
Units:      km/h, rpm
Title:      Speed and engine speed
```

CLI equivalent:

```powershell
python -m tools.PluginGenerator.generator TelemetryGraph `
  --behavior current-and-range `
  --graph time-series `
  --atlas-parameter "vCar:Chassis" `
  --atlas-parameter "nEngine:Chassis" `
  --graph-title "Speed and engine speed" `
  --graph-unit "km/h" `
  --graph-unit "rpm"
```

Units are positional. Fewer units than parameters leaves later units empty. A GUI value such as `km/h, , degC` deliberately skips the middle series. Reordering parameters can change which label applies.

Units are labels, not conversions. Supplying `km/h` does not transform the values.

Titles are XML-escaped. `--no-graph-legend` collapses the panel and makes its grid column zero-width.

## Computed series

### GRAPH-COMP-001: computed series

Computed traces use the first two raw series. Supported operations are `difference`, `sum`, `average`, and safe `ratio`.

```text
GUI: Delta:difference, Combined:sum
CLI: --computed-series "Delta:difference"
```

Check that two raw parameters exist, both receive values, `ComputedGraphSeriesFactory.cs` exists, and view code-behind calls `ComputedGraphSeriesFactory.Create(series)`. Computed traces are created during redraw; they are not ATLAS parameters and create no signal subscription.

The starter implementation combines values by array index, not timestamp interpolation. If series have different timestamp grids, customize the factory to join/interpolate by timestamp before calculating.

## Compare sessions

### COMPARE-TYPE-001: `CompositeSessionKey` conflict

Multiple references can expose the same short type name. Generated code explicitly uses:

```csharp
MAT.OCS.Core.CompositeSessionKey
```

Keep it consistent in tuple declarations, `CompareRowViewModel.Update`, the `CompareSessionValueViewModel` constructor, and its `SessionKey` property. Do not cast between unrelated same-named types.

If the fully qualified type cannot resolve, the project is missing the assembly containing `MAT.OCS.Core` or mixes DLLs from different ATLAS releases.

## XAML diagnostics

### XAML-001: binding failure checklist

Record the binding failure's Data Context, Binding Path, Target, Target Type, and Description. Determine whether the binding originates in generated XAML, ATLAS host chrome, a third-party template, or another plugin. Only fix plugin-owned bindings.

Graph bindings expect:

```text
Series
Name
Unit
CurrentValue (combined behavior only)
Minimum
Maximum
Average
SampleCount
```

Check XML structure with:

```powershell
python -c "import xml.etree.ElementTree as ET; ET.parse(r'PATH_TO_VIEW.xaml'); print('XAML is well-formed')"
```

This proves well-formed XML, not correct WPF binding semantics.

### XAML-002: title breaks XAML

Generated titles are escaped. When hand-editing attributes, encode at least `&` as `&amp;`, `<` as `&lt;`, and double quotes as `&quot;` where necessary.

### XAML-003: unit is empty

Inspect the generated `GraphUnits` array and parameter order in `SyncSeries`. Empty units are allowed. The starter XAML still renders the `Units:` prefix; use a trigger/converter if you want the entire row hidden when blank.

## Breakpoint recipes

### BREAK-001: minimal graph chain

Set in order:

1. Generated `OnMakeTimebaseDataRequestsAsync` at `SignalBus.Send`.
2. Generated `HandleDataResultSignal` at entry.
3. Handler after `Data.ToArray()`.
4. `TimebaseSeriesViewModel.Update`.
5. View code-behind `OnSeriesPropertyChanged`.
6. View code-behind `Redraw`.
7. `GraphRenderer.Draw`.

The first breakpoint not reached identifies the broken boundary.

### BREAK-002: useful watches

Request:

```text
this.ScopeIdentity.Guid
this.DisplayParameterService.PrimaryParameters.Count
parameter.Name
parameter.InstanceIdentifier
compositeSession.TimebaseRange
this.DataRequestSampleCount
```

Result:

```text
signal.SourceId
signal.Data.Request.Parameter.InstanceIdentifier
parameterValues.SampleCount
parameterValues.Data
parameterValues.Timestamp
```

Series/render:

```text

```

### BREAK-003: temporary logging

For temporary local diagnostics, log boundaries rather than every point. `System.Diagnostics.Debug.WriteLine` is convenient because it appears in Visual Studio's Debug output without depending on the installed ATLAS logger overloads:

```csharp
System.Diagnostics.Debug.WriteLine($"Request {parameter.Name}; samples={this.DataRequestSampleCount}");
System.Diagnostics.Debug.WriteLine($"Result samples={parameterValues.SampleCount}; dataNull={parameterValues.Data == null}");
System.Diagnostics.Debug.WriteLine($"Matched series: {series?.Name ?? "<none>"}");
```

Remove or reduce diagnostics after locating the problem.

## Concurrency rules

### THREAD-001: `ParameterValues` ownership

```csharp
parameterValues.Lock();
try
{
    timestamps = parameterValues.Timestamp.ToArray();
    values = parameterValues.Data.ToArray();
}
finally
{
    parameterValues.Unlock();
}
```

Always unlock in `finally`, copy while locked, keep the lock short, retain no mutable ATLAS buffer, and never update WPF while holding the lock.

### THREAD-002: UI dispatch and custom locks

Use inherited `ExecuteOnUiAsync` for UI-bound state. A `SynchronizationContext` field and generic object lock are not generated because the base class and ATLAS value lock cover normal cases. Add a custom lock only for custom shared mutable state accessed concurrently; unnecessary locks can cause deadlocks.

## Build diagnostics

### BUILD-001: generated plugin does not compile

Classify the first error:

| Error | Likely cause |
|---|---|
| namespace/type missing | missing or wrong-version DLL |
| ambiguous type | two namespaces contain the same short name |
| cannot convert same-looking types | distinct assembly types share a name |
| XAML type missing | mapping error or C# build failed first |
| member missing | ATLAS API/version mismatch |

Solve the first error first; later errors often cascade. For composite keys, see `COMPARE-TYPE-001`.

### BUILD-002: validate the generator

```powershell
python -m py_compile tools/PluginGenerator/gui.py tools/PluginGenerator/generator.py
python -m unittest discover -s tests -p test_generator.py
git diff --check
```

Find focused tests with:

```powershell
rg -n "def test_.*(graph|timebase|cursor|compare)" tests/test_generator.py
```

## Configuration reference

### CONFIG-001: behaviors

| Behavior | Cursor | Range | Compare |
|---|---:|---:|---:|
| Basic | no | no | no |
| Current value | yes | no | no |
| Visible range | no | yes | no |
| Current and range | yes | yes | no |
| Compare sessions | composite cursor | no | yes |

A graph requires visible-range or current-and-range behavior.

### CONFIG-002: graph types

Generated types are `time-series`, `scatter`, `histogram`, `bar`, and `custom`. They use native WPF `DrawingContext` and `VisualLayer`; no external chart package is required. Use `custom` for specialized drawing without changing the request pipeline.

## Protections added by the fixes

- `FIX-001`: range requests use `SampleMode.Mean`, matching the handler's use of `ParameterValues.Data`.
- `FIX-002`: compare types consistently use `MAT.OCS.Core.CompositeSessionKey`.
- `FIX-003`: titles are XML-escaped, units follow parameter order, and the legend can collapse fully.
- `FIX-004`: tests assert one `DataResultSignal` subscription and reject the old maximum-to-minimum request mode.

## Final triage order

1. Confirm behavior and graph type.
2. Confirm parameters exist in `PrimaryParameters`.
3. Confirm the range request runs with `SampleMode.Mean`.
4. Confirm request and subscription share `ScopeIdentity.Guid`.
5. Confirm `DataResultSignal` arrives.
6. Confirm arrays are copied while locked.
7. Confirm request parameter GUID matches a series GUID.
8. Confirm `Update` receives finite values.
9. Confirm statistics and notifications update.
10. Confirm `Redraw` gets positive extents and non-empty series.
11. Only then modify renderer or XAML.

This order prevents debugging the renderer when ATLAS returned no data, and prevents debugging requests when the actual fault is a WPF redraw.
